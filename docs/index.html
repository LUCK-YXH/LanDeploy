把 iOS 测试包
送到同事手机上

LanDeploy 在一台电脑上开一个局域网服务，把用 Ad Hoc 描述文件签名的 IPA 分发出去。测试的同学用 iPhone 扫个码就能装，不用连线、不用装工具。

下载最新版 按平台选择

三步

管理端在电脑上操作，设备端只需要扫码。

导入安装包

把已经签好名的 IPA 拖进来。多余的信息——图标、版本、签名类型、描述文件什么时候过期——会自动读出来。

启动服务

点一下「启动」，电脑就成了分发点，并生成二维码。同一个 Wi-Fi 下的设备都能访问。

扫码安装

设备用 Safari 扫码，按提示装包。哪些包是开发版、哪些描述文件快过期了，页面上都标着。

设备端的一次性设置

每台设备只需要做一次，之后扫码即装。

在设备上完成两步
  1. 扫码打开引导页，下载并安装证书描述文件。
  2. 到「设置 › 通用 › 关于本机 › 证书信任设置」开启完全信任。
第二步容易漏。装完描述文件不等于被信任，必须再单独打开那个开关。
为什么会需要证书

分发走的是本地 HTTPS，用的是自签根证书，所以设备要先认识它。 这是 iOS 的要求，且手动安装的根证书必须由使用者亲自开启完全信任—— 没有可以绕过的办法。

常见问题

macOS 说「无法验证开发者」

产物没有做 Apple 开发者签名与公证，系统会拦一次。 右键点击 App → 打开 → 再点一次「打开」即可，之后双击就能正常启动。

macOS 说「已损坏，无法打开」

这两句话听起来像同一件事，其实不是，处理方式也不同：

无法验证开发者是系统不认识发布者——签名是好的，右键打开就行。
已损坏是签名本身校验不过——没有点开的路径，只能清掉隔离标记。

提示「已损坏」说明拿到的是 0.1.0 的旧包，那个版本打包时漏了签名步骤。 请改用 0.1.1 及以上；确实需要救急，就清掉隔离标记： 

xattr -dr com.apple.quarantine /Applications/LanDeploy.app

先把 App 从 DMG 拖进「应用程序」再执行，对着 DMG 里那份执行不生效。

设备上提示「无法安装」

先看管理端列表里的标记：签名校验未通过、描述文件已过期 都能一眼看到。最常见的三个原因是描述文件过期、签名损坏，以及这台设备的 UDID 不在描述文件里。

设备上提示「无法验证此 App 的完整性」

多半是重签名时顺序反了：嵌套的 framework 要先签，主程序最后签。 签完务必复核一次——签名成功不等于签名正确： 

codesign --verify --deep --strict /path/to/YourApp.app

扫码后设备打不开页面

确认两件事：设备与电脑在同一个可互访的局域网（有些 Wi-Fi 会做访客隔离）， 以及电脑防火墙放行了界面显示的那个端口。端口被占时会自动回退到别的端口， 界面上会明确提示——此时之前发出的二维码和链接都已失效。

本工具只负责分发，不负责签名，也不注册设备。 IPA 需要预先用包含测试设备 UDID 的描述文件签名。
